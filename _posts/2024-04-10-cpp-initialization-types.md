## 一、类型决定初始化什么

初始化不是把一段字节简单写入内存。初始化器的语法只是入口，**目标类型决定对象是否需要构造、哪些成员需要递归初始化，以及没有初始值时能否得到确定状态**。

本文回答三个问题：类型如何分类；不同类型在默认初始化、值初始化和列表初始化下有什么差异；如何根据类型选择初始化方式。初始化语法的完整重载解析规则见[C++ 初始化详解](./2024-04-16-cpp-initialization-semantics.md)，对象生命周期与赋值边界见[C++ 初始化与赋值的底层机制](./2024-04-10-cpp-initialization-assignment.md)。

## 二、两组分类：类型来源与初始化行为

### 1、类型来源

**基础类型**由语言直接提供，例如 `int`、`double`、`bool`、`char`、`void` 和 `std::nullptr_t`。

**复合类型**由已有类型组合而成，包括指针、引用、数组、函数、枚举和类类型。`int*`、`int&`、`int[4]` 都属于复合类型。

### 2、与初始化直接相关的行为分类

从初始化角度，更有用的是区分以下三类：

- **标量类型**表示单一值，如算术类型、枚举和指针。初始化通常只需要确定这个值；但局部标量对象没有初始化器时，值仍然不确定。
- **数组和聚合类型**由多个子对象组成。列表初始化按元素或成员声明顺序处理，省略的部分按相应规则初始化。聚合条件随 C++ 标准版本变化，不能简单理解为“没有构造函数”。
- **类类型**通过构造函数建立对象不变量。初始化可能调用用户定义构造函数、复制构造函数或移动构造函数，不能按“位拷贝”推断其行为。

| 类型 | 示例 | `T x;`（默认初始化） | `T x{};`（值/列表初始化） | 初始化关注点 |
|------|------|----------------------|---------------------------|--------------|
| 标量 | `int`、`int*` | 局部对象值不确定；静态存储期对象零初始化 | 得到零值或空指针值 | 不要读取未初始化的局部值 |
| 数组 | `int[3]` | 局部元素值不确定 | 元素按顺序初始化，缺省元素为零 | 不能整体赋值，注意元素初始化 |
| 聚合 | `struct Point { int x; int y; };` | 依成员和存储期决定 | 按成员顺序初始化 | 聚合判定受标准版本影响 |
| 类 | `std::string` | 调用默认构造函数（若存在） | 进行值初始化或匹配构造 | 构造函数决定资源和不变量 |
| 引用 | `int&` | 不允许 | 必须绑定到对象 | 初始化后不能重新绑定 |

## 三、存储期如何改变默认初始化

类型规则和存储期共同决定“没有初始化器”时的结果。静态存储期对象会先进行零初始化；局部自动存储期的内置类型对象若没有初始化器，则值不确定。类类型仍按构造函数建立对象，不能把全局对象的零初始化规则套用到类成员。

```cpp
int global_count; // 静态存储期：零初始化

void f() {
    int local_count; // 自动存储期：值不确定，读取它是未定义行为
    std::string text; // 调用 std::string 默认构造函数，得到空字符串
}
```

类的内置类型成员也遵循成员初始化规则。为成员提供类内初始值，可以让默认状态与对象定义位置无关；构造函数初始化列表提供的值优先级更高。

```cpp
struct Settings {
    int retries = 3;
    bool enabled{true};
};

Settings a;  // 使用类内初始值
Settings b{}; // 列表初始化，同样使用类内初始值
```

## 四、标量、数组和聚合：初始化子对象

### 1、标量类型

标量初始化的核心是确定一个值。复制指针通常只复制地址，不会构造所指向对象；这不等于并发语境下的原子访问。是否能使用该地址，还取决于目标对象的生命周期和同步关系。

```cpp
int count{};       // 0
int* ptr{};        // 空指针值
```

### 2、数组和聚合类型

列表初始化会递归处理子对象：

```cpp
int values[3]{1};  // {1, 0, 0}

struct Point {
    int x;
    int y;
};
Point p{10, 20};    // 按 x、y 的声明顺序初始化
Point origin{};     // 成员值初始化为 0
```

当类型拥有 `std::initializer_list` 构造函数时，列表初始化可能优先选择该构造函数；这属于语法到语义的重载解析问题，详见[C++ 初始化详解](./2024-04-16-cpp-initialization-semantics.md)。

## 五、类、指针和引用：初始化边界不同

### 1、类类型

类类型的初始化由构造函数决定。构造函数可以分配资源、检查参数并建立不变量；复制初始化和移动初始化也可能分别调用复制构造函数或移动构造函数。不能用标量的值复制解释 `std::string`、`std::vector` 等类对象。

```cpp
std::string name{"Ada"};
std::string copy{name};            // 复制构造
std::string moved{std::move(name)}; // 移动构造
```

### 2、指针

指针是复合类型，也是标量类型。它本身可以被初始化为某个地址或空指针值，但不会因为指针初始化而自动初始化指向的对象。所有权应使用明确的资源管理类型表达，例如 `std::unique_ptr<T>`。

### 3、引用

引用是对象的别名，必须在初始化时绑定：

```cpp
int value = 10;
int& ref = value;
// int& invalid; // 错误：引用没有可供默认初始化的状态
```

编译器常见的实现模型是使用指针保存绑定关系，但这是实现细节，不是语言层面的等价定义。引用一旦绑定，后续赋值会修改被引用对象，而不是改变绑定关系。

## 六、根据类型选择初始化方式

可以按以下顺序检查：

1. 目标是引用或 `const` 对象吗？是，则必须在声明处提供合法初始值。
2. 目标是类类型吗？是，则确认需要的构造函数、资源状态和异常安全保证。
3. 目标是数组或聚合类型吗？是，则优先使用列表初始化，让元素按声明顺序建立。
4. 目标是局部标量吗？是，则显式初始化，避免读取不确定值。
5. 需要特定重载而类型有 `initializer_list` 构造函数吗？是，则比较 `{}` 与 `()` 的重载结果，必要时使用[C++ 初始化详解](./2024-04-16-cpp-initialization-semantics.md)中的规则。
